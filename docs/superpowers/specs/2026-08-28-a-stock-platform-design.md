# A股投资策略平台：初始化框架与欢迎页设计

## 1. 背景与目标

项目是一个微信小程序，产品名称为“A股投资策略平台”，核心能力包括每日复盘、个股追踪和策略选股。

第一阶段目标：

1. 建立可独立启动的微信小程序前端和 Node.js/TypeScript 后端。
2. 按领域驱动设计（DDD）建立清晰的接口层、应用层、领域层和基础设施层边界。
3. 完成默认首页/欢迎页，展示产品价值和三个核心能力入口。
4. 使用 MySQL 持久化平台配置和欢迎页内容，前端不得直接连接数据库。
5. 提供健康检查和首页摘要 API，支持后续逐步接入真实金融数据。

## 2. 范围

### 本阶段包含

- 微信原生小程序项目壳、全局样式、底部 Tab 导航。
- 默认首页欢迎页：品牌标题、平台简介、三项能力卡片、今日状态和快捷入口。
- 三个业务域的基础目录与领域边界：`daily-review`、`stock-tracking`、`strategy-selection`。
- 首页摘要查询用例和健康检查用例。
- MySQL 初始化脚本、Prisma Schema、种子数据和环境变量模板。
- 前端 API 客户端、本地兜底内容、加载态和失败态。

### 本阶段不包含

- 真实行情、财务数据、研报或交易接口接入。
- 用户注册、微信登录、权限系统和个性化自选数据。
- 完整的每日复盘编辑后台、选股策略编辑器和复杂量化计算。

## 3. 技术方案

- 前端：微信原生小程序，使用 JavaScript/WXML/WXSS，避免引入当前阶段不必要的跨端抽象。
- 后端：Node.js + TypeScript，使用 Fastify 提供 HTTP API。
- 数据访问：Prisma ORM，MySQL 作为持久化数据库。
- 工程组织：单仓库，前端与后端分目录；后端模块内部按 DDD 分层。
- 配置：`.env.example` 提供数据库连接、服务端口和小程序 API 地址等非敏感配置样例；真实密钥不提交。

## 4. DDD 分层与职责

### 接口层（interfaces）

负责 HTTP 路由、请求参数校验、响应 DTO 和异常到 HTTP 状态码的映射。不包含业务规则，不直接访问 Prisma。

### 应用层（application）

负责用例编排，例如 `GetHomeSummary`。应用服务依赖领域层定义的仓储接口或查询端口，输出面向接口层的结果。

### 领域层（domain）

按业务域放置实体、值对象、领域服务、领域异常和仓储接口。领域层不依赖 Fastify、Prisma 或微信运行时。

### 基础设施层（infrastructure）

负责 Prisma Client、MySQL 仓储实现、配置读取、日志和数据库健康检查。基础设施实现通过依赖注入接入应用层。

## 5. 数据流

1. 小程序启动首页，请求 `GET /api/home/summary`。
2. 接口层调用首页摘要应用服务。
3. 应用服务通过仓储端口读取平台配置与能力入口。
4. 基础设施层使用 Prisma 从 MySQL 查询数据。
5. 接口层返回稳定的首页 DTO；小程序渲染欢迎页。
6. 请求失败时，小程序使用内置兜底文案，并显示可重试提示。

初始数据包括平台名称、简介、三项能力的标题/描述/排序和首页状态文案。未来真实报告、个股和策略结果分别由各自领域提供，不把它们耦合进平台配置表。

## 6. 页面与交互

底部 Tab 导航包含：

- 每日复盘
- 个股追踪
- 策略选股

默认进入首页欢迎页。首页采用深色金融终端风格：突出今日状态和核心入口，使用高对比度文字、绿色/红色仅表达涨跌语义，避免在尚无真实行情时伪造数字。

页面状态：

- 加载态：展示简洁骨架或加载提示。
- 成功态：展示 API 返回内容。
- 失败态：展示本地兜底内容，并提供“重新加载”操作。
- 能力入口：首期展示入口和“即将上线”/状态文案；未实现页面不声称已有真实数据。

## 7. API 初稿

### `GET /api/health`

返回服务状态和数据库连接状态，用于本地启动与部署检查。

### `GET /api/home/summary`

返回：

```json
{
  "productName": "A股投资策略平台",
  "tagline": "用数据，看清每一次市场波动",
  "statusText": "今日市场，保持观察",
  "features": [
    { "key": "daily-review", "title": "每日复盘", "description": "梳理市场脉络，捕捉关键变化", "status": "available" },
    { "key": "stock-tracking", "title": "个股追踪", "description": "持续跟踪关注标的", "status": "coming-soon" },
    { "key": "strategy-selection", "title": "策略选股", "description": "用规则筛选潜在机会", "status": "coming-soon" }
  ]
}
```

实际返回结构以 TypeScript DTO 为准，接口版本预留 `/api` 前缀。

## 8. 验收标准

- 后端可以通过环境变量连接 MySQL，并能执行迁移/种子初始化。
- `GET /api/health` 能区分服务正常和数据库不可用。
- `GET /api/home/summary` 返回三个能力入口，数据来自 MySQL。
- 微信开发者工具可以打开小程序首页，看到欢迎页和底部 Tab。
- API 成功、加载失败、重试三种前端状态可验证。
- 领域层单元测试不需要启动 MySQL；应用层测试覆盖首页摘要用例。
- 项目文档包含启动、环境变量、数据库初始化和前后端运行说明。
